## Формат

- **45 хвилин**, таймер видимий.
- **Думаєш уголос.** Мовчазні 5 хвилин — гірше, ніж неправильна ідея,
  сказана вголос.
- **Тест спершу** там, де змінюється поведінка або контракт.
- Можна: документація Redux Toolkit (`createAction`, `extraReducers`,
  `builder.addCase`), MDN, Vitest, власний код проєкту.
  Не можна: AI-асистенти, розв'язок під спойлером у `layer-separation-step4.md`.
- 2–3 коміти по зелених кроках.

Старт:

```sh
git switch -c live/game-events
npm test        # усе зелене ДО початку
```

## Умова (читається вголос на старті)

> Зараз дії `moveExecuted`, `newGameStarted` і `endGame` народжуються
> всередині `gameSlice` (`gameSlice.actions`). Наступним кроком стан буде
> розбито на три слайси, і всі три реагуватимуть на ті самі події. Якщо
> новий слайс імпортує подію з `gameSlice`, слайси почнуть залежати один від
> одного.
>
> Винеси ці три події в окремий модуль `src/redux/game/gameEvents.js`, який
> не імпортує жодного слайсу. `gameSlice` має обробляти їх як зовнішні
> події. `setSelection` лишається в `gameSlice` як є.
>
> Поведінка гри не змінюється. Типи дій не змінюються. Стан не
> розбивається — це наступна задача.

## Критерії приймання

1. `src/redux/game/gameEvents.js` експортує `moveExecuted`,
   `newGameStarted`, `endGame` і не імпортує нічого з `src/redux/**/*Slice*`.
2. Типи дій ті самі: `'game/moveExecuted'`, `'game/newGameStarted'`,
   `'game/endGame'`. `PERSIST_ON` у `store.js` не змінено.
3. `endGame(...)` без `timestamp` досі додає поточну мить; переданий
   `timestamp` не перезаписується.
4. `gameSlice.actions` містить лише `setSelection`.
5. Усі місця, що диспатчать або тестують ці три події, імпортують їх з
   `gameEvents.js`.
6. `npm test` зелений, жоден тест не видалено. `npm run lint` не додає
   нових помилок у змінених файлах (старі помилки Prettier у проєкті — не
   твоя задача, але назви їх уголос).
7. Ти можеш пояснити, чому ця зміна потрібна **до** розбиття на слайси, а
   не разом із ним.

## Орієнтовний таймлайн

| Хвилини | Що | На що дивиться ментор |
|---|---|---|
| 0–5 | Умова, пошук усіх місць, план уголос | Чи знайдено всіх споживачів подій (код, тести, store) |
| 5–15 | `gameEvents.js` + тест на контракт подій | Тест на тип і `prepare` до переносу, а не після |
| 15–30 | `gameSlice` на `extraReducers`, переімпорти | Тіла редюсерів перенесені без змін |
| 30–38 | Усі тести, lint, червоне — розібратися | Розуміння, **чому** впало |
| 38–45 | Коміти, підсумок уголос, питання 7 | Чи пояснено «навіщо зараз» |

Якщо на 30-й хвилині `gameSlice` ще не зелений — скажи це вголос і
вирішуй, що скорочуєш.

## Підказки

Відкривай по одній, лише якщо застряг більше ніж на 3 хвилини. Кожну
відкриту підказку назви вголос.

<details>
<summary>Підказка 1: з чого почати</summary>

Знайди всіх споживачів: `grep -rn "from '.*gameSlice'" src`. Кожен
рядок, де з `gameSlice` імпортується щось, крім редюсера і `setSelection`,
зміниться.

</details>

<details>
<summary>Підказка 2: де жив <code>prepare</code></summary>

У `createSlice` це `{ reducer, prepare }`. У `createAction` той самий
механізм — другий аргумент. Подивись сигнатуру в документації RTK.

</details>

<details>
<summary>Підказка 3: <code>newGameStarted</code> повертає новий об'єкт</summary>

У `extraReducers` редюсер так само може повернути новий стан замість
мутації. Але подивись, звідки він бере `initialState` — і чи це досі
працює після переносу.

</details>

<details>
<summary>Підказка 4: типи дій</summary>

`createSlice({ name: 'game' })` сам додавав префікс `game/`.
`createAction` нічого не додає: тип — рівно той рядок, який ти передав.
Що станеться з persist, якщо тип зміниться?

</details>

## Для ментора

Розділ нижче кандидат не читає до кінця сесії.

<details>
<summary>Ключ: що має змінитися</summary>

- `gameEvents.js` (новий): три `createAction` з типами `'game/...'`;
  `endGame` з prepare-колбеком `(payload) => ({ payload: { timestamp: Date.now(), ...payload } })`.
- `gameSlice.js`: `reducers` — лише `setSelection`; `extraReducers` з
  `builder.addCase(...)` для трьох подій; тіла без змін (включно з
  `return { ...initialState, ... }` у `newGameStarted`). Експорт — лише
  `setSelection` і редюсер.
- `gameOperations.js`: `moveExecuted`, `endGame` з `./gameEvents`.
- `useGameState.js`: `newGameStarted` з `gameEvents`, `setSelection` — з
  `gameSlice`.
- `store.test.jsx`: `moveExecuted` з `gameEvents`, `setSelection` — з
  `gameSlice`.
- `gameSlice.test.js`: `moveExecuted`, `endGame` з `gameEvents`. Тест
  «prepare додає поточну мить» тепер перевіряє `createAction` — його
  логічно перенести в `gameEvents.test.js`.
- `store.js`, `PERSIST_ON` — без змін.

</details>

<details>
<summary>Ключ: що може піти не так</summary>

| Симптом | Причина |
|---|---|
| Тест «prepare додає поточну мить» падає на `action.type` | тип без префікса: `createAction('endGame')` |
| Партія перестала зберігатися, тести persist червоні | те саме: тип не збігається з `PERSIST_ON` |
| `TypeError: moveExecuted is not a function` у тестах | імпорт з `gameSlice` лишився, а там експорту вже немає |
| `timestamp` у `endGame` перезаписується `Date.now()` | порядок спреду: `{ ...payload, timestamp }` замість `{ timestamp, ...payload }` |
| Цикл імпортів | `gameEvents.js` імпортує `COLORS` або щось через `gameSlice` |

Добрий кандидат пише тест на контракт подій (тип + `prepare`) **до**
переносу, у новому `gameEvents.test.js`: тоді перенос стає рефакторингом
під зеленими тестами.

</details>

<details>
<summary>Ключ: питання 7</summary>

На наступному кроці з'являться `positionSlice` і `uiSlice`, які
реагують на `moveExecuted` і `newGameStarted`. Якщо робити все разом,
одночасно змінюються і джерело подій, і форма стану, і впадуть усі тести
— не зрозуміло, через що. Перенос подій окремо — зміна без зміни
поведінки, яку перевіряють існуючі тести. Той самий принцип, що
«спершу тести, потім розбиття» на 4.0.

Додатково: якщо слайс А імпортує подію зі слайсу Б, а Б колись захоче
подію з А — цикл імпортів. Модуль подій ні від кого не залежить.

</details>

<details>
<summary>Рубрика оцінювання</summary>

| | 1 — слабко | 2 — норм | 3 — сильно |
|---|---|---|---|
| **Комунікація** | мовчить | коментує дії | спершу план, потім дії; каже «не знаю, перевіряю ось так» |
| **Тести** | без нових тестів | тест на подію після переносу | тест на контракт подій до переносу |
| **Діагностика** | правит, поки не позеленіє | читає помилку | пояснює причину до правки |
| **Обсяг** | розбиває слайси, чіпає старі помилки lint | робить задачу | робить задачу і явно називає, що свідомо не робить |
| **Git** | один коміт | кілька комітів | коміти по зелених кроках з осмисленими назвами |
| **Контракт** | тип дії змінено | тип збережено випадково | тип збережено свідомо, пояснено зв'язок з persist |

Червоні прапорці: змінений `PERSIST_ON` замість збереження типів;
видалений тест `prepare`; `gameEvents.js` імпортує слайс; переписані тіла
редюсерів «заодно».

</details>
