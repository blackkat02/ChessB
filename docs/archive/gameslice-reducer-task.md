# Таска: навести порядок у `gameSlice.js` і розібратися з редюсером

Дата: 2026-10-04. Частина кроку 2 з `docs/layer-separation.md`.
Попередній документ: `docs/layer-separation-step2-fix.md`, розділ 4.2.

Мета цієї таски — не "щоб тести позеленіли", а щоб ти **міг пояснити кожен
рядок** `moveExecuted`: звідки береться значення, хто його використовує і
чому рядок стоїть саме тут. Код — лише наслідок розуміння.

Правило на всю таску: **не закоментовуй рядки, щоб "подивитися, що буде".**
Якщо не розумієш рядок, зупинись і заповни для нього таблицю з етапу 2.

## Етап 0. Зупинись і повернись до робочого стану

Зараз у файлі суміш старого й нового коду. Її неможливо зрозуміти, бо вона не
працює ні як стара, ні як нова версія:

| Рядок | Що не так |
|---|---|
| 32 | `moveExecuted: (state)` — немає параметра `action`, а рядок 33 його читає → `ReferenceError` |
| 4, 56–57 | `isCheck` / `isCheckmate` закоментовані, але `givesCheck` використовується в рядках 63 і 87 |
| 59, 62, 83–85 | `isPromotion`, `pieceToPlace`, `captured`, `castling`, `enPassant` ніде не оголошені |
| 40–44 | у знімку "до ходу" закоментовані права рокіровки й ціль взяття на проході — нотації вони потрібні |
| — | **ніхто не переставляє фігури**: немає ні старої логіки, ні виклику `applyMove` |
| 51–55 | "позиція після ходу" — насправді позиція **до** ходу, бо дошку ніхто не змінив |

Що зробити:

1. Збережи свою поточну версію на згадку (не обов'язково):
   `cp src/redux/game/gameSlice.js gameSlice.wip.js` (у корінь, не в `src`).
2. Відкоти файл до останнього робочого стану:
   `git restore src/redux/game/gameSlice.js`
3. У ньому виправ **лише два імпорти** (наслідок кроку 1):
   `../../utils/boardUtils` → `../../engine/boardUtils`,
   `../../utils/chessHelpers` → `../../engine/chessHelpers`.
4. `npx vitest run src/redux/game/gameSlice.test.js` → **усе зелене**.

Тепер у тебе є **відома точка, де все працює**. Від неї рухаємось маленькими
кроками й після кожного запускаємо тести. Якщо щось почервоніло, знаєш, що
зламав саме останній крок.

> Чому так: рефакторинг — це зміна форми коду **без зміни поведінки**. Якщо
> почати з коду, який уже не працює, неможливо відрізнити "зламав я" від
> "було зламано".

## Етап 1. Прочитай робочий редюсер і розріж його на блоки

Відкрий відновлений `moveExecuted` (приблизно 110 рядків) і **постав
коментарі-заголовки** над кожним блоком. Код не змінюй, лише розмічай:

```js
moveExecuted: (state, action) => {
  // ── [1] ВХІД: що прийшло в action ─────────────────────
  // ── [2] ЗНІМОК ДО ХОДУ ───────────────────────────────
  // ── [3] ШАХИ: переставити фігури ─────────────────────
  // ── [4] ШАХИ: нові права рокіровки / на проході ──────
  // ── [5] ШАХИ: шах/мат суперника ──────────────────────
  // ── [6] ЗАПИС: SAN ───────────────────────────────────
  // ── [7] ЧАС: Date.now(), годинник ────────────────────
  // ── [8] ЗАПИС: history, plyCount, selectedSquare ─────
},
```

Перевір себе:

- Скільки рядків припало на блоки [3] і [4]? Саме цю частину ми забираємо в
  `applyMove`.
- Чи є рядок, який ти не зміг віднести до жодного блоку? Запиши його й
  розберись, перш ніж іти далі.

## Етап 3. Порядок має значення

Дай письмові відповіді (одне-два речення):

1. Чому знімок "до ходу" робиться **першим**, до будь-яких змін `state`?
2. Чому статус шаху й мату рахується **після** того, як фігури переставлені,
   а не до?
3. Чому `clockAfter` у history береться **після** того, як годинник зменшено?
4. Що станеться з SAN, якщо `buildSan` отримає позицію **після** ходу замість
   позиції до?

<details>
<summary>Звір</summary>

1. Далі редюсер змінює `state.board` (через Immer). Без знімка "до"
   й "після" стали б одним об'єктом, а нотації потрібна саме позиція до ходу.
2. Шах дає хід. До ходу фігура ще не стоїть там, звідки атакує короля.
3. `clockAfter` — це "скільки лишилось після цього ходу". Якщо взяти раніше,
   запишеться час до списання.
4. Дизамбігуація зламається: у позиції після ходу фігура вже стоїть на `to`,
   а на `from` порожньо. Перевірка "чи могла інша така сама фігура піти на
   `to`" дасть хибну відповідь, і замість `Nbd2` вийде `Nd2` або навпаки.

</details>

## Етап 4. Заміна блоків [3] і [4] на `applyMove`, маленькими кроками

**Передумова:** у `applyMove.js` заповнено `details`. Зараз там усі чотири
поля `undefined`, і без них тести на `captured`/`castling`/`enPassant`/`promotion`
не пройдуть. Що повертати — див. `layer-separation-step2-fix.md`, розділ 2, баг 3.

Після **кожного** підкроку запускай:

```
npx vitest run src/redux/game/gameSlice.test.js
```

### 4.1. Підключи `applyMove`, нічого не видаляючи

Додай імпорт `import { applyMove } from '../../engine';`. На початку редюсера,
**поряд** зі старим кодом, а не замість нього, виклич:

```js
const before = {
  board: state.board,
  castlingRights: state.castlingRights,
  enPassantTarget: state.enPassantTarget,
};
const { position, details } = applyMove(before, action.payload);
console.log('applyMove →', position, details); // тимчасово
```

Тести мають лишитися зеленими: ти нічого не змінив, лише порахував. Подивись
у вивід консолі тестів: чи збігаються `details` з тим, що рахує старий код?
Це твоя ручна перевірка, що `applyMove` працює так само.

### 4.2. Заміни запис позиції

Видали старі блоки [3] і [4] (перестановка, `castlingRights`, `enPassantTarget`)
і натомість:

```js
state.board = position.board;
state.castlingRights = position.castlingRights;
state.enPassantTarget = position.enPassantTarget;
```

Тести впадуть там, де далі використовуються `captured`, `castling` тощо. Це
очікувано, переходь до 4.3.

### 4.3. Заміни старі змінні на `details`

- `captured` → `details.captured`
- `castling` → `details.castling`
- `enPassant` → `details.enPassant`
- `promotionPiece` → `details.promotion`

Тести мають знову позеленіти. Якщо ні, порівняй, що повертає `applyMove` і
що чекає тест (`toBeNull()` проти `undefined`, `'Q'` проти `'q'`).

### 4.4. Прибери зайві знімки

- `gameStateBeforeMove` з копією `{ ...state.board }` більше не потрібен,
  бо в `buildSan` передавай `before`. Подумай: **чому тепер копія не потрібна?**
- `gameStateAfterMove` більше не потрібен: в `isCheckmate` передавай `position`,
  а в `isCheck` — `position.board`.
- Прибери `console.log` з 4.1.

Тести зелені? Переходь далі.

### 4.5. Прибери імпорти

`algebraicToCoords`, `coordsToAlgebraic`, `requiresPromotion`,
`resolvePromotionPiece` редюсеру більше не потрібні. Видали їх. Лінтер
(`no-unused-vars`) підкаже, якщо щось пропустиш.
