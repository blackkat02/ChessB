## Дані, з якими працюємо

```js
// дошка — об'єкт: ключ — клітинка, значення — FEN-символ фігури
const board = { e1: 'K', e8: 'k', c3: 'N' };

Object.keys(board); // ['e1', 'e8', 'c3']            — клітинки
Object.values(board); // ['K', 'k', 'N']               — фігури
Object.entries(board); // [['e1','K'], ['e8','k'], ['c3','N']] — пари
```

Королі є завжди (по одному з кожного боку), тому їх можна не рахувати.
Важливо лише, **що ще** лишилось на дошці:

| Без королів         | Мат можливий?                 | `isInsufficientMaterial` |
| ------------------- | ----------------------------- | ------------------------ |
| нічого              | ні                            | `true`                   |
| `['N']` або `['b']` | ні                            | `true`                   |
| `['P']`             | так (пішак стане ферзем)      | `false`                  |
| `['R']`, `['q']`    | так                           | `false`                  |
| `['N', 'N']`        | так, якщо суперник помилиться | `false`                  |
| `['B', 'n']`        | так, якщо суперник помилиться | `false`                  |

FIDE рахує нічию лише тоді, коли мат неможливий **жодною** послідовністю
ходів, навіть якщо суперник грає навмисно погано. Тому два коні — не нічия.

## Критерії приймання

1. `getNonKingPieces` повертає **масив**, навіть порожній.
2. `isInsufficientMaterial` повертає **булеан** у кожній гілці — ніколи
   `undefined`.
3. `isInsufficientMaterial` викликає `getNonKingPieces`, а не дублює цикл.
4. Тип фігури перевіряється через `getPieceType`, а не `=== 'n' || === 'N'`.
5. Два коні й «слон проти коня» — `false`.
6. Тести, які треба було дописати, дописані; `npm test` зелений.
7. Ти можеш пояснити, чому два коні — не нічия, хоча поставити ними мат
   у реальній партії майже неможливо.

## Підказки

Відкривай по одній, лише якщо застряг більше ніж на 3 хвилини.

<details>
<summary>Підказка 1 (крок 1): масив фігур</summary>

`Object.values(board)` дає масив фігур. `filter` лишає ті елементи, для
яких колбек повертає `true`. Колбек отримує фігуру (`'k'`, `'N'`), а
повертати має «це не король».

</details>

<details>
<summary>Підказка 2 (крок 2): одна фігура</summary>

Якщо в масиві рівно один елемент, він лежить у `pieces[0]`. Його тип —
`getPieceType(pieces[0])`. Підходять два типи — дві умови через `||`.
Можна одразу `return` цієї умови: вона сама вже булеан.

</details>

<details>
<summary>Підказка 3 (крок 3): «кожен»</summary>

`[...].every(колбек)` → `true`, якщо колбек повернув `true` для **кожного**
елемента. Для пари `[square, piece]` колбек може розібрати її одразу:
`([square, piece]) => ...`. Якщо клітинка не потрібна — `([, piece]) => ...`.

</details>

<details>
<summary>Підказка 4 (крок 3): колір першого слона</summary>

Спершу зроби масив кольорів через `map`: `['dark', 'dark']`. Потім
`every`: чи кожен елемент дорівнює `colors[0]`?

</details>

<details>
<summary>Ключ</summary>

```js
import { getPieceColor, getPieceType, getOpponentColor } from './chessHelpers';

export function getNonKingPieces(board) {
  return Object.values(board).filter((piece) => getPieceType(piece) !== 'K');
}

export function getSquareColor(square) {
  const fileIndex = 'abcdefgh'.indexOf(square[0]);
  const rank = Number(square[1]);
  return (fileIndex + rank) % 2 === 0 ? 'light' : 'dark';
}

export function isInsufficientMaterial(board) {
  const pieces = getNonKingPieces(board);
  if (pieces.length === 0) return true;

  if (pieces.length === 1) {
    const type = getPieceType(pieces[0]);
    if (type === 'N' || type === 'B') return true;
  }

  // крок 3: лише слони, усі на клітинках одного кольору
  const others = Object.entries(board).filter(
    ([, piece]) => getPieceType(piece) !== 'K'
  );
  const allBishops = others.every(([, piece]) => getPieceType(piece) === 'B');
  if (!allBishops) return false;

  const colors = others.map(([square]) => getSquareColor(square));
  return colors.every((color) => color === colors[0]);
}
```

Після кроку 2 (до слонів) гілка з однією фігурою може бути
`return type === 'N' || type === 'B';`, а кінець функції — `return false;`.
У кроці 3 обидва варіанти гілки (`return умова` і `if (умова) return true`)
правильні: одна тура все одно дає `false` — або одразу, або на правилі
слонів. Хороше питання вголос: «чи потрібна ще гілка з однією фігурою, якщо
є правило слонів?» — для слона ні, для коня так.

Stretch 1: так, перевірку «порожньо» можна прибрати — `[].every` дає `true`,
масив кольорів порожній, `[].every(...)` знову `true`. Але явна перевірка
читається краще; важливо, щоб кандидат перевірив це тестом.

Коміти: `feat(engine): add getNonKingPieces helper`,
`feat(engine): detect K vs K and single minor piece as insufficient material`,
`feat(engine): detect same-colour bishops as insufficient material`.

</details>

<details>
<summary>Ключ: пастки</summary>

**Повертає `undefined`.** Гілка `if (pieces.length === 1)` без `return` в
кінці функції: для пішака функція повертає `undefined`, а `toBe(false)`
падає. Типова помилка (див. сесію #5: `false` замість `[]`).

**`=== 'K'` без `getPieceType`.** `filter((p) => p !== 'K')` лишає чорного
короля `'k'` → для «король проти короля» масив `['k']`, функція бачить одну
фігуру не-кінь-не-слон → `false`. Тест «король проти короля» це ловить.

**`=== 'n' || === 'N' || === 'b' || === 'B'`.** Працює, але критерій 4.
Питання: «навіщо ми робили `getPieceType`?»

**Два коні — `true`.** Кандидат вирішує «кінь не може матувати» і перевіряє
лише типи, а не кількість. Тест «два коні» червоний. Пояснення — таблиця з
розділу «Дані»: допоміжний мат конями існує.

**Колір через `charCodeAt`.** `square.charCodeAt(0) - 97` — правильно, але
незрозуміло без коментаря. `indexOf` у рядку `'abcdefgh'` читається краще.

**`Number(square[1])` забуто.** `0 + '1'` → `'01'` (рядок), `% 2` дає 1 —
випадково правильно для `a1`, але `'7' + '1'` → `'71'` → непарне → h1 темна.
Тест на `h1` це ловить.

**Колір клітинки за кольором фігури.** Плутанина «білий слон — світлий».
Колір **клітинки** не залежить від кольору фігури: білий слон на `c1` —
темнопільний.

</details>
